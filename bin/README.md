# Служебные скрипты `bin/`

Схема общая с traktoristy/polurama: разработка локально, штатная выкладка —
autoUpload PhpStorm, скрипты — контроль и фолбэк. Запускаются с рабочей
машины (Git Bash), на сервер ходят по SSH сами. Код возврата обоих — 1 при
провале, годится для автоматики.

Зачем `deploy.sh`, если есть autoUpload: PhpStorm возит правки, только пока
IDE открыта — изменения, сделанные из CLI при закрытой IDE, на прод не
уезжают (случалось). Скрипт закрывает эту дыру и никогда не трогает ядро
Bitrix — только кастом (`public_html/local/`, `index.php`, `.htaccess`),
исключая документацию: `CLAUDE.md` живут в репозитории, на сервере им нечего
делать.

`smoke.sh` — строго читающий смоук боевого сайта: пин-пад, форма логина
админки, 404 фейковой share-ссылки, закрытость исходников, статика темы,
`php -l` боевым PHP, дрейф деплоя, хвост журнала ошибок. Путь дневника не
зашит — читается с сервера из `b_option`.
