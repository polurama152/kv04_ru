# 0002 — Производительность и версионирование

- Статус: `in-progress`
- Дата: 2026-08-21, обновлено 2026-08-31
- Модуль: `kv04.diary`, инфраструктура репозитория

Хроника — [`docs/JOURNAL.md`](../JOURNAL.md): замеры, закрытый долг с датами,
ловушки площадки, ошибочные записи. Здесь остаётся то, что ещё не сделано.

## Зачем

Приоритет продукта — мгновенный отклик при любом объёме контента и числе
пользователей. Замеры показали, что упирается не в объём данных (12 заметок),
а в накладные расходы на каждый запрос. Плюс проект не имел версионирования
при `autoUpload=Always`: любая правка уезжала на прод без возможности отката.

## Решение

**Версионирование.** `git init`, ветка `main`, remote
`git@github.com:polurama152/kv04_ru.git`. Из репозитория исключены ядро
Bitrix (5.7 ГБ), `upload/`, дампы, `cgi-bin/` (28 МБ бинарников прежнего
хостинга) и всё, что содержит пароли: `.settings.php`, `dbconn.php`.
`.gitattributes` держит LF — сервер Linux.

**`Installer::ensure()`.** Вызывался дважды за запрос (`index.php` и
`executeComponent()` обоих компонентов) и каждый раз выполнял ~10 запросов
старым API плюс два безусловных `INSERT INTO b_option`. Каждый показ главной,
включая гостевой, писал в базу; под конкурентной нагрузкой это упёрлось бы в
блокировку двух одних и тех же строк.

- статический флаг `$ensured` — повторный вызов в том же запросе бесплатен;
- опция `schema_version` — выход без единого запроса, если схема применена;
- `setOption()` сверяет значение перед записью;
- `ensure(true)` — принудительное переприменение;
- идентификаторы HL и инфоблока проверяются отдельно, поэтому ручное удаление
  сущностей приводит к повторному созданию, а не к тихому пропуску.

Вызовы в компонентах оставлены: модуль должен быть самодостаточным у клиента
Маркетплейса, а стоимость повторного вызова теперь нулевая.

**Контроль выкладки (2026-08-29).** autoUpload PhpStorm возит правки только
при открытой IDE: правки из CLI молча не уезжали (так на прод не доехал
`admin/menu.php`). Появился `bin/` по образцу traktoristy/polurama:
`deploy.sh` — сверка md5 кастома (`public_html/local/`, `index.php`,
`.htaccess`) с продом и доставка расхождений по scp, ядро Bitrix не трогает;
`smoke.sh` — восемь строго читающих проверок боевого сайта (пин-пад, форма
логина админки, 404 фейковой share-ссылки, закрытость исходников, статика
темы, `php -l` боевым `/usr/bin/php8.4`, дрейф деплоя, хвост журнала).
Подробности — `bin/README.md`.

## Вне скоупа

N+1 в `NoteService::list()`, счётчик `ipfail_*` в `b_option`,
локальный highlight.js, переезд с shared-хостинга — вынесено в долг ниже.
Первые три с тех пор закрыты, см. журнал; переезд остаётся.

## Контракт

Опция модуля `kv04.diary`: `schema_version` — строка, живое значение в
`Installer::SCHEMA_VERSION`. Поднимать при изменении структуры HL или
инфоблока: это заставит `ensure()` один раз переприменить схему.

Сигнатура: `Installer::ensure(bool $force = false): void`. Поведение при
`$force = false` и применённой схеме — no-op.

## Долг

**Безопасность.**

- **Apache 2.2.29 на площадке**, сборка 2021 года. Ветка закрыта
  разработчиками в 2018-м, обновлений безопасности по ней нет. Из-за неё же в
  `.htaccess` не работает синтаксис 2.4.
- **Медиа отдаётся по прямым публичным адресам** — решение принято
  сознательно 2026-08-24, но последствие записываем: кто знает адрес файла,
  тот его откроет, и **отзыв ссылки на дневник этого не отменяет**. Закрыть
  можно страницу, а не адрес уже показанной картинки. Чтобы отзыв работал
  по-настоящему, медиа пришлось бы отдавать через PHP с проверкой — это
  минус скорость и плюс нагрузка, и пока цена выше пользы.
- **Появилась публичная страница** `/d/<32 hex>` — первая поверхность
  дневника, доступная без пина. Что сделано сразу: токен из 16 случайных
  байт, поиск по уникальному индексу; несуществующий и отозванный токен
  отвечают одинаково (404), поэтому по ответу не видно, была ли ссылка;
  компонент `kv04:diary.share` не принимает POST вовсе; страница закрыта
  `noindex`. Чего пока нет: ограничения частоты запросов к этой странице —
  перебор токенов бессмыслен, но нагрузку никто не сдерживает. Тот же
  предохранитель нужен перебору личных адресов (спеки `0005`, `0006`).
- **`debug => true` в `exception_handling`** (`bitrix/.settings.php` на
  проде, замечено 2026-08-29): при исключении Bitrix может печатать трейс в
  ответ. Выключить debug, лог (`bitrix/modules/error.log`) оставить — его
  уже читает `bin/smoke.sh`.
- **Файлы модуля исполняются по прямому URL** (замечено 2026-08-29):
  `/local/modules/kv04.diary/lib/auth.php` отвечает 200 — классы без
  пролога исполняются впустую, но исполнение по прямому адресу лишнее.
  Закрыть `.htaccess`-ом в `local/modules/` (`php_flag engine off` — PHP по
  HTTP выключается, `include` из кода и отдача `assets/` не страдают).
  Смоук уже стережёт худший вариант — отдачу исходника текстом.

**Производительность.**

- Сессии в файлах — блокировка сериализует параллельные запросы одного
  посетителя. Замер 2026-08-23: два одновременных запроса с одной сессией —
  0.105 с, с разными — 0.084 с, одиночный — 0.080 с. Папку унесли из общего
  `/var/tmp`, но файловая природа осталась; лечится Redis, то есть переездом.

**Инфраструктура.** Shared-хостинг Beget — потолок для цели «мгновенный
отклик». Redis и Memcached недоступны, кэш Bitrix файловый. Замер 2026-08-23:
сервер отдаёт главную за 79–93 мс изнутри, а до браузера ответ идёт 0.77–1.3 с
при load average 9 на общей машине — транспорт и соседи по железу стоят
дороже, чем весь PHP. Следующий шаг — VPS 4 vCPU / 8 ГБ / NVMe: nginx +
PHP-FPM без Apache, Redis под сессии и кэш, HTTP/2 и HTTP/3. Ожидаемо
120 мс → 25–40 мс.
