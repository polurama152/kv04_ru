# 0006 — Адрес вместо почты: регистрация по адресу

- Статус: `done`
- Дата: 2026-08-31
- Модуль: `kv04.diary`

## Зачем

Регистрация просила почту, хотя дневнику она нужна не как связь, а как ответ
на вопрос «чей это дневник». Личный адрес (спека `0005`) отвечает на тот же
вопрос и вдобавок служит дверью и адресом приложения на телефоне. Поэтому при
регистрации спрашиваем адрес, а не почту.

## Решение

- **Адрес — идентичность.** Регистрация: адрес + пин + повтор пина. Вход с
  личного адреса — один пин: адрес уже сказал, чей дневник.
- **Почта осталась, но необязательной.** Единственный путь назад, если
  забыты и адрес, и пин: без неё восстанавливать не через что. Поле рядом,
  подписано «только чтобы вернуть доступ», можно пропустить и добавить позже
  полоской в ленте (`attach_email`).
- **Одно поле на общей странице принимает и адрес, и почту.** Отличает их
  собака в строке. Заставлять человека вспоминать URL целиком, когда он
  пришёл на общую страницу, было бы издевательством.
- **Занятость адреса сообщаем прямо** (решение владельца 2026-08-31): адреса
  публичны, как ники. Попытка стоит места в лестнице блокировок по IP,
  поэтому перечислять их подряд дорого. Цена решения: регистрация — оракул
  существования адресов; страница дневника при этом по-прежнему неотличима
  (спека `0005`), но скрывать существование адреса больше не цель.
- **Смена адреса ничего не теряет.** Данные привязаны к внутреннему
  `OWNER_ID`, адрес — только дверь. Прежний адрес не достаётся другим и ведёт
  на **общую** страницу, а не на новый адрес: адрес меняют в том числе чтобы
  уйти от знавших прежний. Установленное приложение продолжает открываться.
- **Свой прежний адрес можно занять обратно** — метка переезда снимается.

## Вне скоупа

Восстановление письмом (почта собрана, но писем модуль не шлёт), перенос
дневника между аккаунтами, несколько адресов на владельца.

## Контракт

- `PinService::create(string $slug, string $pin, string $confirm, string $email = '')`
  → `{ok, url}` (адрес нового дневника) либо `{ok:false, error}`.
- POST `create` компонента `kv04:diary.pin`: `slug`, `pin`, `pin_confirm`,
  `email` (необязательно); при успехе фронт уходит на `url`.
- Поле входа `email` принимает адрес или почту; ошибка — «Неверный адрес,
  почта или пин».
- `kv04_diary_slugs.MOVED_AT`: 0 — действующий адрес, иначе время переезда.
  Схема данных — версия `10`.
- `SlugService::isTaken()`, `isMoved()`; `save()` метит прежний адрес
  переехавшим вместо удаления.
