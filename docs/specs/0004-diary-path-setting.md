# 0004 — Путь дневника: настройка вместо корня

- Статус: `done`
- Дата: 2026-08-30
- Модуль: `kv04.diary`, `index.php`, `urlrewrite.php`

## Зачем

Дневник монопольно занимал корень kv04.ru, а корень нужен магазину. Клиенту
Маркетплейса тем более нельзя перехватывать главную. Путь дневника стал
настройкой: например `day` — дневник живёт на `/day`, папка не создаётся.

## Решение

- **Виртуальный путь через штатный `urlrewrite.php`.** `.htaccess` и так
  заводит несуществующие адреса в `bitrix/urlrewrite.php`; модуль держит там
  именованные правила (`ID => kv04.diary`, снимаются и ставятся заново одним
  `Path::applyRewrite()`): страница, `sw.js`, `manifest.webmanifest` — всё
  с настроенного пути.
- **Настройка из приложения — главный вход.** В панели дневников строка
  «Настройки» → панель с полем пути. Право: Bitrix-админ всегда, владелец
  пина — при флаге `owner_settings` (Маркетплейс-дефолт `N`; сам флаг
  из приложения не меняется — только в админке, иначе владелец выдал бы
  права сам себе). Параллельный вход — `options.php`
  (`settings.php?mid=kv04.diary`), пункт «Настройка» в админ-меню. Обе
  точки пишут одну опцию и зовут один `applyRewrite()`.
- **Шелл страницы переехал в модуль** (`pub/index.php`), сам поднимает
  пролог — им пользуются и корневой `index.php`, и urlrewrite. Корневой
  `index.php` — диспетчер: `?d=` → шелл (share-ссылки глобальные, розданные
  живут), путь пуст → шелл, иначе `301` на путь.
- **PWA под путь**: scope воркера определяется URL, поэтому `sw.js` отдаёт
  посредник `pub/sw.php` (urlrewrite включает только `.php`), а манифест —
  `pub/manifest.php`, который берёт `start_url`/`scope` из адреса запроса и
  ядро не поднимает. Шелл снимает воркеры прежних путей (только свои, по
  имени `sw.js`) — иначе офлайн-фолбэк корня накрыл бы магазин.
- **Дефолты**: живой сайт при обновлении получает `''` (корень, поведение
  не меняется), свежая установка — `diary` (`DoInstall`, признак свежести —
  пустой `hlblock_id`). Схема данных: `SCHEMA_VERSION = 8`.

## Вне скоупа

Магазинная главная на корне (отдельная задача; пока корень — 301), перенос
`/d/` под путь, вкладка прав в options.php.

## Контракт

- Опции: `path` (строка, `[a-z0-9_-]` с сегментами через `/`; `bitrix`,
  `local`, `upload`, `d` заняты), `owner_settings` (`Y|N`).
- `Kv04\Diary\Path`: `raw()`, `base()` `'/day'|''`, `url()` `'/day/'|'/'`,
  `normalize()`, `collides()` (файл/папка с тем же именем перехватит адрес —
  предупреждение при сохранении), `save()`, `applyRewrite()`.
- POST `action=settings_save` (`path`) в `diary.feed` → `{ok, path, url}` |
  `{ok:false, error}`; при смене пути фронт уходит на новый адрес.
- kv04.ru: путь `day`, корень `301 → /day/`.

## Файлы

- `local/modules/kv04.diary/`: `lib/path.php`, `pub/{index,sw,manifest}.php`,
  `options.php`, `lang/{ru,en}/options.php`, `admin/menu.php`,
  `lib/installer.php`, `install/index.php`, `include.php`
- `public_html/index.php` (диспетчер), `bin/smoke.sh` (`DIARY_PATH`)
- воркер: `assets/pwa/sw.js` (переехал из корня), статический манифест
  заменён на `pub/manifest.php`

## Долг

- Маркетплейс: `pub/` поедет в пакет как есть; правила ставит установка.
- Миграционный `unregister` чужих scope в шелле — убрать, когда старые
  регистрации на корне вымрут (не раньше осени 2026).
